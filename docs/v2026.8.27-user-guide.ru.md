# Hermes Agent v0.20.6 / v2026.8.27 — практическая справка

Эта памятка относится к runtime после применения профиля PatchKit `v2026.8.27-*`. До активации новой базы команды и UI старого runtime не обязаны содержать эти возможности.

## Сначала: не запускать `hermes update` в PatchKit runtime

Для обычной upstream-инсталляции `hermes update --plan` показывает план обновления и `hermes update` выполняет его. В этом окружении source of truth — PatchKit: прямой updater заменит checkout и обойдёт overlay. Переход выполняется через manifest/profile PatchKit, отдельный backup и проверку apply; не через `hermes update`.

После будущей активации сначала проверить версию:

```bash
hermes --version
hermes-gateways status
```

Нужны `v0.20.6` / `v2026.8.27` и ожидаемые profile-scoped gateway units. Если хоть один gateway всё ещё показывает старый код, сначала устранить code skew, а не включать новые настройки.

## 1. MCP catalog: самый прикладной новый каталог интеграций

Когда нужен готовый удалённый MCP-сервер (например, Cloudflare, Grafana Cloud, Better Stack или Railway), сначала просмотрите каталог:

```bash
hermes mcp catalog
```

Затем установите ровно один нужный entry:

```bash
hermes mcp install <name>
```

Установка интерактивно спрашивает нужные credentials и позволяет выбрать включаемые tools. Секреты вводятся только в prompt/профильный secret store; не добавляйте их в PatchKit manifest или обычный YAML. После установки начните новую беседу (либо перезапустите затронутый gateway), чтобы новая tool surface была построена заново и не нарушала prompt cache уже идущей беседы.

Когда применять:
- Cloudflare — управление зоной, Workers и observability через официальный hosted MCP;
- Grafana/Better Stack — только для конкретного мониторингового запроса;
- Railway — только для задач выбранного deployment.

Не ставьте весь каталог «на всякий случай»: каждая интеграция расширяет доступную tool surface и требует отдельной оценки прав.

## 2. Lean-tail compression: длинные диалоги по умолчанию стали устойчивее

В v0.20.6 `compression.tail_mode: lean` является default. При сжатии Hermes сохраняет ограниченный свежий хвост (2.5% context window, минимум 10K, максимум 25K tokens), а старую середину переносит в summary с индексом идентификаторов и дословными user messages. Это уменьшает разрастание контекста в длинных agent-сессиях.

Обычно ничего включать не нужно. Посмотреть текущую настройку можно так:

```bash
hermes config show | grep -A 12 '^compression:'
```

Если требуется прежнее консервативное поведение с большим verbatim tail, только после проверки качества конкретной длинной сессии:

```bash
hermes config set compression.tail_mode legacy
```

Где применять:
- `lean` — дефолт для обычных долгих рабочих чатов, cron и gateway-сессий;
- `legacy` — кратковременная диагностика, если нужно сравнить поведение с прежним runtime.

Не меняйте mode внутри уже активного разговора. Начните новую сессию: системный prompt и tool surface должны оставаться byte-stable в течение текущей беседы.

## 3. Более быстрый web search / web extract

Результаты `web_search` и `web_extract` теперь получают TTL cache. Пользоваться нужно теми же инструментами: повторный близкий запрос обычно быстрее и не требует ручной настройки.

Применять cache хорошо для:
- повторного анализа одного документа в рамках исследования;
- нескольких вопросов к одному и тому же публичному сайту.

Не полагайтесь на cache для котировок, статусов инцидентов, availability и других быстро меняющихся данных: для них всегда просите live-проверку и явно указывайте, что данные должны быть свежими.

## 4. Улучшенный tool search

Поиск инструментов теперь делает несколько query-вариантов и stem matching. Пользовательская привычка простая: формулируйте цель, а не выдумывайте имя tool.

Хорошо: «найди актуальный status gateway и последние ошибки».
Плохо: «вызови несуществующий `gateway_health_v2`».

Это особенно полезно в больших toolset-ах после установки MCP catalog entries.

## 5. Новые модели в picker

В picker появились, среди прочих, GLM-5.3-Flash, MiniMax M3 free и MiniMax H3 Max video. Откройте picker обычной командой:

```text
/model
```

или настройте provider/model только после того, как соответствующий provider авторизован в выбранном profile. Модель выбирается для новой сессии либо стандартным безопасным lifecycle Hermes; не подменяйте provider или toolset вручную посреди активного разговора.

Практический выбор:
- Flash/free модели — быстрые недорогие черновики, классификация, короткие задачи;
- более сильная/video модель — только когда задача действительно требует соответствующего качества/модальности и provider доступен.

Не включайте незнакомый provider «наугад»: сначала подтвердите условия, лимиты и куда будут уходить данные.

## 6. Desktop Browser и личный Chromium profile

Desktop Browser получил собственное OS window, а использование реального Chromium profile сделано consent-gated. Это не означает, что Hermes автоматически читает cookies или аккаунты.

Подключать уже запущенный Chromium-family browser следует только при явной необходимости и согласии, через существующий flow:

```text
/browser connect
```

Подходящие случаи: работа с уже авторизованным внутренним сайтом, когда вы явно хотите использовать текущую browser-сессию. Не использовать для фонового или незаметного доступа к личным аккаунтам.

## 7. Несколько профилей и gateway fleet

Для нескольких локальных Hermes profiles проверяйте состояние сразу всех gateway:

```bash
hermes-gateways status
```

В v0.20.6 updater и Desktop лучше показывают fleet/profile состояние и code skew. Это средство наблюдения, не повод включать multiplexing автоматически. Текущие profile isolation, allowlists, secrets и отдельные systemd units нужно сохранить как есть. Любое изменение `gateway.multiplex_profiles` требует отдельного плана и проверки routing, а не является частью этого re-anchor.

## 8. Что изменилось в надёжности без ручной настройки

После активации автоматически действуют:
- более безопасное завершение дочерних процессов по timeout;
- cron durable incident acknowledgements и более понятная диагностика code-skew;
- updater, который при штатном upstream-обновлении использует control socket для паузы gateway вместо tree-kill;
- отказ от небезопасного in-place update для image/package-managed инсталляций.

Это не новые команды для ежедневной работы, а причины применять стандартные lifecycle-команды Hermes вместо ручного `kill -9` или прямой замены файлов runtime.
